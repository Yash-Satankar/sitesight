What SiteSight does

Drawings → BOQ

Muse Spark reads the structural sheets; code assembles the BOQ. Anything the drawings don't state is marked "needs input".

SAM detects, Muse Spark verifies

SAM 3.1 finds columns and brickwork; Muse Spark rejects scaffolding, rebar cages, tarps and neighbours before anything is counted.

Stages, not guesses

Staged items are judged by the latest completed stage (shuttering → reinforcement → concreting); code turns that into a percentage.

Asks for the photo it needs

When it can't see enough, it requests one specific, phone-only photo instead of guessing.

Observed vs inferred

Hidden work deduced from what's visible is listed separately and never billed until a photo shows it.

Bill-ready PDF

The engineer accepts, edits or undoes each item; the report lists evidence photos with the masks that were counted.

Built with Meta

Muse Spark

Runs the agent: looks at photos, verifies detections, decides stages, writes rationales, asks for photos, and reads drawing sheets into strict JSON.

SAM 3.1

Segments every column and brick wall in a photo, with masks and scores, so progress is counted instead of eyeballed.

Muse Voice Transcribe

Turns the engineer's voice note on a photo into text the agent reads as context.

Honest limitations

  • Perspective. A wall bay's built share is measured in image pixels; an angled photo over- or under-states the far side. The agent asks for square-on photos, but doesn't correct for it.
  • SAM is weak on rebar and slabs, so those are judged visually by Muse Spark, with confidence capped.
  • Inferred items are a judgement call. They stay out of the bill, but the engineer still has to confirm them.

Roadmap

  • WhatsApp intake: forward site photos to a number instead of opening the app.
  • Hindi and Marathi voice notes.
  • Rate-based billing: BOQ rates × measured quantities → the running bill itself.
